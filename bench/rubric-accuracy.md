# 评审任务：列出两份回答的准确度差距点

你是独立评审。不要修改任何文件，只写指令要求的输出文件。被问的仓库路径写在评审指令里。

题目文件里每题有：问题、回答 A、回答 B。回答可能带图（图是截图，路径写在题目文件里，**请打开看**），也可能只有文字。

**读者**：一名工程师，要为这部分代码的改动签字。他不是这部分代码的作者。

## 任务

只看准确度，不评价可读性、篇幅、版式。两份回答都要查，标准相同。

1. 从代码确定：回答这个问题必需的主要阶段、关系和判断是什么。
2. 逐条核对两份回答的关键说法和图上的每条关键路径或关系，到源码确认。
3. 列出每一个差距点。
4. 给每份回答的正确性打分（0–30）：说法是否与代码一致；说错关键机制、编造文件或函数名，重扣；缺主干算错，在这一项扣分；缺次要细节不扣分，讲得更全也不加分。

**算差距点：**

- `wrong`：说法或图与代码不符。
- `missing-main`：缺少回答问题必需的主要阶段、关系或判断。
- `misleading`：每句话都不算错，但读者会得到错误结论。例如图上没有写条件，读者认为这一步总是发生。

**不算差距点：** 缺次要细节；风格；没有行号；你无法从代码确认的怀疑。

每个差距点都必须有代码证据（文件:行号）。没有证据就不要写。

## 输出

只输出一个 JSON，不要其他文字：

```json
{"questions":[{"id":"d1-flow",
  "正确性":{"A":0,"B":0},
  "A":[{"type":"wrong","where":"diagram","severity":"high","claim":"回答说了什么（图要写出是哪条边或哪个节点）","code":"代码实际怎样","evidence":"文件:行号","source":"text-same"}],
  "B":[],
  "note":"一句话说明这一题两边准确度的主要差别"}]}
```

- `where`：`text`、`diagram` 或 `both`。
- `severity`：`high` = 读者照此判断会做错决定；`medium` = 主要机制有偏差；`low` = 小偏差。
- `source`：文字和图的关系，取值 `text-same`（一样错）、`text-right-diagram-wrong`、`text-wrong-diagram-right`、`only-text`、`only-diagram`。没有图的回答填 `only-text`。
