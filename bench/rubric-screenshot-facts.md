# 评审任务：只看截图，按主要事实比较几份回答的准确度

你是独立评审。不要修改任何文件，只写指令要求的输出文件。被问的仓库路径写在评审指令里。

题目文件里每题有：问题，和几份回答（A、B、C）。每份回答都是**截图**，就是读者看到的内容。回答的内容只有截图，请逐张打开。

**读者**：一名工程师，要为这部分代码的改动签字。他不是这部分代码的作者。

## 同一把尺

- 一份回答的文字和图是一个整体。不管这个事实写在文字里还是画在图上，都同样算。
- 图和文字一样，只按主要事实核对。**不要逐条核对图的边、节点和顺序。** 图的说法比文字多、更容易查，不能因此多扣分。
- 回答的形式（有没有图、长短、版式）不加分也不扣分。

## 步骤

1. **先定事实，再看回答。** 打开任何截图之前，先读代码，列出回答这个问题必需的 5–8 条主要事实（阶段、关系、判断）。每条必须有代码证据（文件:行号）。次要细节不算主要事实。这个清单对每份回答都一样，看过回答后不要改。
2. **逐份核对。** 对每条事实，给每份回答一个结果：
   - `right`：说对了（文字或图说对，另一边没有矛盾）。
   - `wrong`：说错了（文字和图都错，或只有一边说到且说错）。
   - `conflict`：文字和图互相矛盾。
   - `unsaid`：没有说到。
3. **其他严重错误。** 清单之外，只记读者照此判断会做错决定的错误，要有代码证据。小偏差、简化、缺次要细节都不记。
4. **打分。** 给每份回答的正确性打 0–30：主要事实是否说对。说错或缺主要事实要扣分；讲得更全不加分。

你无法从代码确认的怀疑不要写。

## 输出

只输出一个 JSON，不要其他文字：

```json
{"questions":[{"id":"d1-flow",
  "facts":[{"fact":"一句话写清这条事实","evidence":"文件:行号","A":"right","B":"wrong","C":"unsaid"}],
  "severe":{"A":[],"B":[{"claim":"回答说了什么","code":"代码实际怎样","evidence":"文件:行号"}],"C":[]},
  "正确性":{"A":0,"B":0,"C":0},
  "note":"一句话说明这一题几份回答准确度的主要差别"}]}
```
