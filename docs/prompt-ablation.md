# 提示词消融（2026-11-05）

## 判断标准（第一性原理）

提示词的作用只有一个：让模型做出产品需要、而它自己不会做的事。所以一条规则有必要，只有两种情况：

1. 模型不可能自己知道：产品的协议和格式（什么时候提交、段落怎么带动图、图的 JSON、程序怎么核对证据）。删掉就画不出来或被程序退回。
2. 删掉后实测变差：读者得到的回答变差（Opus 盲评），或者更慢、更贵、被退回更多。

下面两种情况的规则没有必要：

3. 工具定义或程序已经给了：工具的字段说明写了，或者程序会检查并退回（模型从退回的消息里就知道怎么改）。
4. 模型不说也会这样做。

## 规则分组

`src/prompt.js` 把规则分成块。核心块（情况 1）每个版本都保留；其余 7 组可以单独去掉（`RC_PROMPT_DROP`）。

| 组 | 内容 | 字符 | 假设 | 理由 |
|---|---|---|---|---|
| 核心 | 身份；什么时候画图、什么时候用普通消息；submit_answer 协议；段落和图怎么对应（view、now、upto、[[文字\|id]]）；证据格式（quote 原样抄，程序按它核对）；8 种图的 JSON 格式 | 3575 | 必要 | 情况 1 |
| L 语言 | 用提问的语言回答 | 85 | 不必要 | 程序检查语言并退回；模型默认跟着提问的语言 |
| S 范围 | 流程两头都要讲到；模块列全；关卡讲清条件 | 189 | 待测 | 质量规则 |
| A 准确 | 只依据仓库代码；证据 30 行内、优先源码；最容易想当然的一点要验证；准确第一 | 511 | 待测 | 质量规则；以前去掉“关键判断”后评委找出的错误变多（8 → 10、11） |
| X 探索 | 先搜后读、用 offset/limit；一次并发几个调用；10 步左右提交 | 162 | 待测 | 影响时间 |
| W 写给读者 | 白话、专业词解释、代码名最多 3 个；不堆路径；take 长度、followups | 388 | 部分必要 | 代码名上限程序会退回（退回要多等约 1 分钟）；“白话”是产品目标 |
| C 选图 | 每类问题用哪种图；条件步骤用 opt/alt 框 | 619 | 待测 | 模型看了格式也能自己选，但不一定选对 |
| R 目录说明 | areas 怎么写 | 188 | 不必要 | 工具字段说明里已经写了 |

## 方法

- 被测仓库 `../deepseek-harness`（8bd073392e，跑前跑后都没有改动）。模型 DeepSeek-V4.1-Flash，推理 high，`dsh --profile rc-headless`，工具：read、grep、glob、PowerShell（只读沙箱）。
- 题目：`bench/questions.json` 的 q1–q11（每类问题一题；q11 是新加的“能做什么”）。每个版本每题跑 1 次。
- 第一轮：完整版对最小版（只留核心）。第二轮按第一轮的结果定。
- 指标：
  - 自动（`bench/ablate-metrics.mjs`）：是否提交了带图的回答、用时、步数、输出 token、退回次数和原因、段落数、每段代码名、证据核对率、图的种类是否对应问题类型。
  - Opus 盲评（`bench/judge.mjs`）：同一题两份回答 A/B 随机排列，评委自己读代码核对，打分（1–10），列错误，判哪份更好。以前测过：同一份回答三次评分在 ±0.5 内波动。

## 结果

### 第一轮：完整版对最小版（7 题：q1 q2 q3 q4 q7 q9 q11，`bench/out/abl-full`、`abl-min`、`judge-abl-min`）

| | 完整版 | 最小版（只留核心） |
|---|---|---|
| 提交了带图的回答 | 7/7 | 7/7 |
| 平均用时 / 步数 | 147 s / 18.7 | 150 s / 22 |
| 输出 token（每题） | 20.2K | 21.3K |
| 终端调用（7 题合计） | 23 | 45 |
| 被程序退回 | 0 | 1（一段 4 个代码名） |
| 每段代码名（平均） | 0.49 | 1.34 |
| 证据核对通过 | 98% | 98% |
| 用文档（*.md）当证据 | 14 条 | 21 条 |
| 图的种类对应问题类型 | 7/7 | 7/7 |
| 目录说明（每题） | 5.9 | 5.9 |
| Opus 盲评（平均分） | 7.79 | 7.57 |
| 哪份更好 | 6 题 | 1 题 |

评委说最小版差在哪：6 题都说术语和代码名多、不写代码的人看不懂（W）；q4 写了一句没有依据的“本次会话为只读”，把自己运行环境的状态当成了仓库的行为（A 的第一条）；q1 模块列得不全（S）。

### 结论

| 组 | 结论 | 证据 |
|---|---|---|
| 核心 | 保留 | 协议和格式，模型无从知道 |
| L 语言 | 保留 | 去掉后英文题交了中文，退回重写多花约 1 分钟 |
| S 范围 | 保留 | 最小版 q1 模块列不全（评委）；只有一轮，证据弱 |
| A 准确 | 保留 | 最小版把运行环境当成仓库行为（q4）；文档证据 14 → 21 条 |
| X 探索 | 保留 | 和 S、A 一起时去掉 X，步数和用时明显增加（q1 20 → 40 步）。推测是 S、A 让模型多查，X 给了上限 |
| W 写给读者 | 保留 | 去掉后代码名 0.49 → 1.34 个/段，评委 6 题指出难懂，1 次退回 |
| C 选图 | 删除 | 不说也选对了 7/7；去掉后盲评不降 |
| R 目录说明 | 删除 | 工具字段说明已经够了：目录数相同（5.9） |

最终提示词 4910 字符（原来 5717；核心 3575）。

### 限制

- 每题每个版本只跑 1 次；评委对同一份回答的打分有约 ±0.5 的波动。结论靠的是方向一致（6/7）和评委给出的原因，不是平均分差。
- 只测了 deepseek-harness 一个仓库、DeepSeek-V4.1-Flash 一个模型。
- 第二轮的候选版同时去掉了 4 组，L、X 的作用是从自动指标看出来的，C、R 没有单独去掉测过。
- 花费：DeepSeek 跑题 22 次；Opus 盲评 10 次，3.62 美元。
